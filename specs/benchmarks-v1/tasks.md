## Phase 8 — review round (PR #75)
- [x] T8.1 Rebase onto the merged interop work. *(2026-09-29: the branch was stacked on `af1f2cb`, 11 commits behind #74, so the benchmark code had never run against the adapter it ships with — including the in-process REPL lock. Rebased onto `origin/master` at `0677697`.)*
- [x] T8.2 Two or more providers no longer lose their official cells. *(The official engine admits one in-process run at a time process-wide and a queued run gives up rather than waiting out its budget, so the matrix's own thread pool left a two-provider grid with one official cell and one "engine busy" failure — a benchmark manufacturing its own failures. `MatrixBenchmarkRunner._execute_slots` now runs official slots through a `max_workers=1` pass while the other engines stay parallel, and skips that entirely under `--sandbox docker`, where each run gets a container. Reviewer reproduced the original failure with a trial merge; `TestOfficialSlotsShareOneInProcessREPL` pins the batching.)*
- [x] T8.3 Counting answers are matched on number boundaries. *(Every counting case expects a bare number under `contains`, and `"72" in "it appears 172 times"` scored a wrong count as correct, inflating accuracy on exactly the hardest cases. `matches()` now requires a numeric expectation to appear as its own number; text expectations are unchanged.)*
- [x] T8.4 A judge failure no longer voids a paid run. *(A rate limit or dropped connection raised through `_score` into the CLI, which caught only `ValueError`/`OSError`, so hours of provider calls ended in a traceback with no output files. The judge call is now guarded per cell (`SlotOutcome.judge_error`, rendered as a missing score, never a fabricated 3.0), `parse_judge_json` rejects a reply that is not an object instead of returning a list, the CLI writes `results.partial.json` for whatever completed, and a `RuntimeError` exits with a message rather than a traceback.)*
- [x] T8.5 Wrapped phrases are counted. *(The pinned RFC 9110 is hard-wrapped, so `\bMUST\ NOT\b` missed 5 occurrences: the derived target was 72 where the text has 77, and a model that counted correctly was scored wrong. Verified by downloading the pinned file — digest matches — and counting both ways. `count_word` / `count_phrase` now treat the gaps inside a phrase as any whitespace run.)*
- [x] T8.6 A corrupt download is replaced, not reused. *(A file failing its digest stayed in `benchmarks/corpus/`, and fetching skips files that exist, so every later run failed until someone deleted it by hand. It is now discarded — with an error naming `--fetch` when no fetch was requested — and downloads land through a `.part` file so an interrupted one is never mistaken for a complete corpus.)*
- [x] T8.7 Correct the over-tight number boundary from T8.3. *(2026-09-29: the first fix rejected any number followed by `.` or `,`, but edge punctuation is only stripped from the ends of the whole answer, so a count that ended a sentence or a clause — "77. This includes…", "the count is 17, based on…" — was marked wrong. Accuracy on the counting cases was understated instead of inflated: the same defect, reversed. The trailing guard now rejects a digit, or a separator followed by a digit, so "172"/"720"/"72,000"/"72.5"/".72" still fail for 72 while punctuation after the number passes. Both of the reviewer's examples are tests.)*
